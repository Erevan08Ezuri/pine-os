# PineOS audit and repair — September 12, 2026

Source baseline: `be034e5` on `main`. The audit covers the shared C++ services,
Finance persistence and workflows, Files sandbox, Notes/input/rendering, desktop
startup/shutdown, Tab5 SQLite VFS, display completion callback, and build/package
paths. This is a tested repair pass, not a claim that every possible bug has been
eliminated or that the physical Tab5 has been certified.

## Repairs

| Area | Finding and resulting behavior |
| --- | --- |
| Files | `.` and normalized root aliases could remove or rename the entire sandbox. Root mutations are rejected. Renames/moves cannot overwrite existing files; recursive self-copy is rejected, and directory copies skip symlinks. |
| Settings and PIN storage | Settings removed the old file before committing the new one; PIN replacement was incompatible with Windows rename behavior. Both now use a checked temporary write and recoverable backup/rename sequence. A failed PIN write does not replace the active in-memory credential. |
| PIN authentication | A short stored digest was indexed as if it contained 64 characters. Invalid digest/salt lengths fail authentication before comparison. |
| Finance locking | An immediately expiring background timestamp caused successful unlocks to relock on the next foreground update. Background expiration now applies only while backgrounded or returning from background. |
| Modal input | Prompts and confirmation overlays allowed clicks to reach underlying controls. Hit testing now respects the active modal layer and rendering clip; navigation clears abandoned prompts. |
| UI lifecycle | Shell services and input callbacks were destroyed after SDL shutdown. The shell now closes first. Finance content is clipped above its navigation bar. |
| UTF-8 | Font rendering/measurement interpreted UTF-8 bytes as separate glyphs, and note wrapping split characters. Rendering and wrapping now decode codepoints. Unsupported font glyphs remain subject to the bundled font's coverage. |
| Finance imports | Duplicate rows within a single CSV/OFX import could be booked twice. Ledger entries, balance changes, and fingerprints now commit together under a transaction, with live duplicate checks. OFX identifiers are scoped by account while recognizing older raw IDs. |
| CSV/OFX validation | Preview accepted impossible calendar dates. Validation now checks calendar dates, and CSV reads handle CRLF and quoted multiline records. |
| Finance backup/restore | Restore accepted unrelated SQLite files. It now checks integrity, the Pine schema/version, and foreign-key consistency before replacing data. Backup/restore also checks both copy-step and finish results and closes handles on failure. |
| Database recovery | General initialization failures could be mislabeled corruption. Automatic quarantine now applies only to SQLite corruption/not-a-database errors and preserves sidecar files; newer schemas are left intact. |
| Balance changes | Deletion could overflow balances and reconciliation could commit an intermediate incorrect balance. Reversals now use checked arithmetic and atomic writes; reconciliation records the final balance in its snapshot. Snapshot comparisons avoid signed overflow and ordering includes a tie-breaker. |
| Budget identity | Updating an existing budget returned a newly generated ID that was never stored. The persisted ID is now returned. |
| Validation | Transaction/transfer/bill/subscription/goal dates are validated; negative budget/goal values are rejected. Goal contribution arithmetic is checked. Malformed historical bill dates no longer crash reminder generation. |
| Currency totals | Dashboard and cash-flow totals combined unrelated currency units. They now use the selected default currency; the overview labels that currency, and individual transactions retain their own currency labels. No exchange-rate conversion is performed. |
| Exact money | Subtraction incorrectly rejected valid operations involving the minimum signed integer. Bounds checks now handle subtraction directly; a bare decimal is rejected as money. |
| Tab5 SQLite VFS | Path aliases could create independent lock groups for the same database. VFS filenames are canonicalized before locking. Host tests exercise alias contention, rollback, and reopen persistence. |
| Tab5 display callback | IDF can invoke transfer completion from either DMA ISR or synchronous task paths. The callback now uses the matching FreeRTOS semaphore API and rejects uninitialized presentation calls. |
| Build and firmware validation | CI bypassed PSRAM validation, and `flash` could implicitly build and flash without the gate. Both now run the gate; commented config text cannot satisfy it. Headless CI uses SDL's console-build option, publishes acceptance images, and applies the required SQLite mutex adaptation before VFS testing. |

## Verification

- GCC 13.3 desktop Debug build with AddressSanitizer and UndefinedBehaviorSanitizer.
- Original native service/persistence suite, plus 18 audit regression scenarios.
- Four Python firmware-gate cases, including proof that an invalid config never invokes flash.
- Real SDL software-rendered acceptance scenarios: boot, home, settings, simulated Bluetooth/camera, Files, Notes editing/search/deletion/keyboard, Finance views, lock screen, developer controls.
  All 18 scenarios passed in both RGBA32 and RGB565 (36 rendered frames total);
  representative final RGB565 screens were visually inspected.
- Tab5 VFS compiled and executed on the host using the pinned SQLite 3.50.4 sources and the firmware's rollback-journal/mutex configuration.
- Native ESP32-P4 firmware cross-build with ESP-IDF 5.5.1 completed and produced
  the application, bootloader, partition table and flash arguments. Packaging
  verified 200 MHz HEX PSRAM and disabled PSRAM XIP.
  The application is `0x401050` bytes and leaves 43% of its application partition free.

Six Finance regressions were observed failing before their repairs: budget identity,
calendar validation, transaction reversal overflow, downward reconciliation, import
preview dates, and accepting unrelated backups. Subsequent checks also exercise
failure rollback, per-account OFX IDs, multibyte text, selected-currency totals,
modal click routing, settings recovery, malformed PIN digests and lock timing.

LeakSanitizer is disabled because this execution environment runs under tracing,
which LeakSanitizer does not support. ASan bounds/use-after-free checks and UBSan
remain enabled. Passing these scenarios is not an exhaustive memory/leak proof.

## Reproduce

```sh
cmake -S . -B build/audit -DCMAKE_BUILD_TYPE=Debug \
  -DSDL_X11=OFF -DSDL_WAYLAND=OFF -DSDL_UNIX_CONSOLE_BUILD=ON \
  -DCMAKE_CXX_FLAGS="-fsanitize=address,undefined -fno-omit-frame-pointer" \
  -DCMAKE_EXE_LINKER_FLAGS="-fsanitize=address,undefined"
cmake --build build/audit --parallel 2
ASAN_OPTIONS=detect_leaks=0 UBSAN_OPTIONS=halt_on_error=1 \
  ctest --test-dir build/audit --output-on-failure
SDL_VIDEODRIVER=dummy ASAN_OPTIONS=detect_leaks=0 \
  build/audit/bin/pine --data=build/audit-data --acceptance=build/audit-images
```

Use a fresh `--data` directory for deterministic acceptance fixtures. Add
`--rgb565` to render with the Tab5 pixel format. Desktop camera/radio controls
are simulations, not evidence of physical hardware operation.

For firmware, open an ESP-IDF 5.5.1 terminal and run `python3 platform/tab5/tab5.py build`.
In this authoring environment, Component Manager 2.2.2 was used because 2.5.2
failed while inspecting the sandbox's process tree. Source dependency versions
remain pinned. The stock SDK QEMU tools support ESP32/ESP32-C3, not ESP32-P4;
therefore no full Tab5 CPU/peripheral emulation is claimed.

## Physical checks still required

The prior LCD underrun report cannot be cleared using the desktop simulator.
Verify both panel revisions where available, touch corners and release behavior,
Wi-Fi reconnect/NTP/RTC, display stability during note saves and Finance imports,
stack/internal-memory headroom, power-loss recovery, and updating without erasing
user storage. The existing 200 MHz HEX-PSRAM and conservative panel clock settings
are retained and checked during packaging.

Camera capture, Bluetooth pairing/audio, USB mass storage/host keyboard, microSD
browsing, and battery percentage remain unimplemented on Tab5 as documented in
`TAB5.md`. Budgets/goals retain the existing default-currency convention; this is
not a currency-conversion system. Large-data reporting/import limits and sustained
device performance remain acceptance areas, not proven by these small fixtures.
